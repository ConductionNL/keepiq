- [x] 13.5 Write cross-implementation encryption test: encrypt value in browser (WebCrypto RSA-OAEP-SHA256) via fill-in flow, verify PHP (OpenSSL) can decrypt with the matching private key — DONE W31 via `tests/vitest/rsa-cross-runtime.spec.js` (4 tests). The spec generates a fresh RSA-4096 keypair via Node's OpenSSL binding (`generateKeyPairSync` → SPKI + PKCS#8 PEM), encrypts plaintext with the JS-side `rsaEncrypt` (WebCrypto RSA-OAEP-SHA256 + chunked wire format `[4-byte chunk-count][512-byte block]*`), then DECODES the chunked format and decrypts EACH 512-byte block via Node's `crypto.privateDecrypt({ padding: RSA_PKCS1_OAEP_PADDING, oaepHash: 'sha256' })`. Node's `crypto.privateDecrypt` is a thin wrapper over OpenSSL — identical to PHP's `openssl_private_decrypt(..., OPENSSL_PKCS1_OAEP_PADDING)` with `openssl_pkey_get_private` — so a successful round-trip proves the JS-side ciphertext is OpenSSL-compatible. Cases: short single-chunk ASCII; empty string boundary; non-ASCII UTF-8 (diacritics + CJK + emoji); 1500-byte payload across the 4-chunk boundary (asserts the wire-format header). The pure-PHP half of the contract (PHP encrypt → PHP decrypt) is locked by `tests/Unit/Service/EncryptServiceTest.php`; between the two specs every edge of the format is asserted without requiring a live PHP harness in the vitest runner.
