Keepiq test site

Login forms to try the extension on. Nothing you submit is stored or logged. Save a login in Keepiq with the URL http://localhost:8100 to get fill suggestions here. Cards and identities are offered on every page, whatever their URL.

  • Basic loginUsername and password in one form. Fill, save bar, redirect chain after submit.
  • Email loginEmail field with autocomplete hints and a "remember me" checkbox.
  • Multi-step loginUsername first, password on the next page.
  • Hidden honeypot fieldA hidden password field next to the real one. Only the visible one may be filled.
  • Shadow DOMThe form lives inside an open shadow root.
  • IframesA same-site iframe that should fill, and a cross-site one that should not.
  • Framework-controlled inputsInputs that only see values set with input events, as in React.
  • Login without a formNo <form> element, sent with fetch.
  • Login and sign-up without a formA login panel, a sign-up panel, a newsletter and a header "Sign up". Only the login panel is a login.
  • Autocomplete offA login with autocomplete="off", which is ignored: fill, list and save bar work.
  • Mislabelled loginA login password marked new-password, still treated as a login.
  • Inline listWhere the list beneath a field opens and where not: scrolling, iframes, sign-up, disabled fields, the guard cases, masks and assistive styling.
  • Root filter and the top layerA probe: filter: opacity(0) on <html> and a popover. Shows whether the filter reaches this browser's top layer, which the inline list's guard assumes on Firefox and Safari.
  • Login in a modal dialogA login in a showModal() dialog, a transformed one and an ARIA modal with a focus trap. The list shows inside each and a pick fills.
  • Sign upNew password and confirmation. Save bar for a new login.
  • Change passwordCurrent, new and confirm. Update bar for a changed password.
  • Two-step setupA QR code and key to scan or paste into a login's Authenticator key in Keepiq, which every code page below checks against.
  • QR code without a keyA setup-like page whose QR code holds a website. Scanning it sets no key.
  • Login with two-step verificationA login, then a code step in the layout you pick: one field, two halves or six boxes.
  • One-time codeThe second step after a login, with one code field.
  • One-time code in two halvesTwo inputs of three with a dash between them.
  • One-time code in six boxesSix one-character inputs that move focus along.
  • Login with a codeUsername, password and code in one form; one fill fills all three.
  • Recovery codeA recovery code field marked one-time-code. Not a code field: no list, no fill.
  • PasskeyRegister a passkey and sign in with it. The page checks both with WebCrypto and shows the counter.
  • Passkey in the field's suggestionsA conditional passkey request on load and a webauthn username field. The list offers passkeys above the logins.
  • Passkey in a same-origin frameThe passkey page in a frame on this origin. Keepiq handles it as the page itself; in Safari its fallback waits for the frame's focus.
  • Passkey in a cross-origin frameThe passkey page in a frame on another origin. Its requests go to the browser, never to Keepiq.
  • Login submitted by scriptThe page fills and submits a login itself, as a probe of the vault would. No save or update bar.
  • Card checkoutA checkout with cc-* tokens and a type=password CVC. The card list on every field, never the login list, and no save bar.
  • Card in split fieldsMonth and year selects, a card type select, a number in four boxes and a combined "MM / YYYY" expiry.
  • Card checkout in DutchDutch labels without tokens, an "MMJJ" expiry and a PIN field that stays empty.
  • Card fields in frames"Name on card" in the page and the card fields in a same-site and a cross-site frame. Keepiq asks before filling the cross-site one, and again for a frame added after the answer.
  • Address formsName parts, email, phone and a multi-line address, a first address line, a full name and a Dutch form. The identity list and fill.
  • Sign up beside a loginA sign-up form with a first name and an email username, a login with an email and a newsletter. Only the sign-up form gets the identity list.
  • Hidden card and address fieldsCard and address fields hidden by opacity, aria-hidden, inert, off-screen positioning, clipping, a cover or a zero-height wrapper. Only the shown fields are filled.
  • Card and address fields no scrolling reachesFields fixed off-screen, below the fold of a page that cannot scroll, or in a scrolling box with no room or under a cover. Only the shown fields are filled; those just past the end of a scrolling box are too.
  • NewsletterAn email field with "Subscribe". Not a login: no list, no fill, no save bar.
  • No login formAn article without login fields. The popup says autofill is not available; a fill from the context menu says no form was found.
