Keepiq test site

Login forms to try the extension on. Nothing you submit is stored or logged. Save a login in Keepiq with the URL http://localhost:8100 to get fill suggestions here.

  • Basic loginUsername and password in one form. Fill, save bar, redirect chain after submit.
  • Email loginEmail field with autocomplete hints and a "remember me" checkbox.
  • Multi-step loginUsername first, password on the next page.
  • Hidden honeypot fieldA hidden password field next to the real one. Only the visible one may be filled.
  • Shadow DOMThe form lives inside an open shadow root.
  • IframesA same-site iframe that should fill, and a cross-site one that should not.
  • Framework-controlled inputsInputs that only see values set with input events, as in React.
  • Login without a formNo <form> element, sent with fetch.
  • Login and sign-up without a formA login panel, a sign-up panel, a newsletter and a header "Sign up". Only the login panel is a login.
  • Autocomplete offA login with autocomplete="off", which is ignored: fill, list and save bar work.
  • Mislabelled loginA login password marked new-password, still treated as a login.
  • Inline listWhere the list beneath a field opens and where not: scrolling, iframes, sign-up, disabled fields, the guard cases, masks and assistive styling.
  • Login in a modal dialogA login in a showModal() dialog, a transformed one and an ARIA modal with a focus trap. The list shows inside each and a pick fills.
  • Sign upNew password and confirmation. Save bar for a new login.
  • Change passwordCurrent, new and confirm. Update bar for a changed password.
  • One-time codeThe second step after a login, with a code field.
  • Login submitted by scriptThe page fills and submits a login itself, as a probe of the vault would. No save or update bar.
  • NewsletterAn email field with "Subscribe". Not a login: no list, no fill, no save bar.
  • No login formA page without login fields. The popup should say autofill is not available.
