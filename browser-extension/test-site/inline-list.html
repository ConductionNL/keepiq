Same-origin iframe

On this origin, like every frame above it: the list opens inside the frame on Chrome and Firefox, and a pick fills only the frame.

Same-site iframe

On port 8101 of localhost, which the test site also serves: the same site but another origin, so no list opens, on Chrome or Firefox.

Cross-site iframe

On 127.0.0.1, another origin: no list opens, not even the "no logins" one, on Chrome or Firefox, with or without the mask. Open this page on 127.0.0.1 to frame the localhost login from another origin instead.

Too-small iframe

120 px tall, with room for one row above and one below the field: no list opens, whatever the vault holds.

Double-click

Guard cases

Press a button, then focus a login field (the one below for the first eight, the frame for the last four). The page tampers with the list once it opens. Clear the field between tries.

  • The page is invisible for 5 s, but the list sits in the top layer, so a pick fills on Chrome and Firefox 125 and later; on Firefox below 125 nothing is filled and the list stays open, showing "Keepiq can't fill here".
  • The page is invisible until the field loses focus, but the list sits in the top layer, so a pick fills on Chrome and Firefox 125 and later; Firefox below 125 refuses it.
  • A pointer-events: none box covers the list, so on Chrome a click through it shows "Keepiq can't fill here" instead of filling, while Firefox does not catch this.
  • After 1 s the page hides and re-shows the list's host: the list closes.
  • After 1 s the page sets an outline on the host: the list closes.
  • Its !important rules leave the host as it is, but the ::after it draws over the list takes the click, so the list closes and nothing fills, without a message.
  • The page root is scaled, which leaves the top-layer list as it is, so a pick fills on Chrome and Firefox 125 and later; Firefox below 125 refuses it.
  • The page root is zoomed, which resizes the list, so a pick is refused on every browser.
  • The frame's wrapper is invisible for 5 s, during which Chrome never delivers a click to the list, so nothing fills and the rows stay without a message, and only a click within 500 ms after the wrapper is restored shows "Keepiq can't fill here".
  • The frame's wrapper is rotated, which the list inside the frame cannot escape, so a pick is refused on every browser, and on Chrome shows "Keepiq can't fill here".
  • The frame's wrapper is only moved with transform: translate(...), so a pick fills on every browser.
  • The frame's wrapper gets mask-image: linear-gradient(transparent, transparent) for 5 s. Click where a row is: the pick is refused.

Assistive styling

Inverts the page with a filter on <html>, as Dark Reader's filter mode does: on Chrome the top-layer list keeps its own colours and a pick fills, while on Firefox, any version, the filter reaches the list too and a pick shows "Keepiq can't fill here because this page changes how it is shown. Use the Keepiq button in the toolbar." instead.
